# Open questions (need the user)

Decisions were made where possible; these are the ones worth confirming.

1. **Entra app registration.** We need tenant id, client id, client secret, and
   the redirect URI `${PUBLIC_URL}/auth/callback` registered as a *Web*
   platform redirect. Should login be restricted to the home tenant only
   (default: yes, single-tenant issuer `…/{tenant}/v2.0`)?

2. **Anonymous share links.** Design assumes every viewer must log in; "share"
   = room URL + a grant (`all logged-in users` or specific e-mails). If
   link-only access for people without an Entra account is wanted, that is a
   new principal kind (`link:<secret>`) — not hard, but a deliberate choice.

3. **Who may create at the top level?** Default: only admins can create
   folders/rooms directly under root (others need an `editor` grant on root
   or a sub-folder). Alternative: `all = editor` on root so anyone can create.

4. **Retention.** Files are never deleted and rooms are soft-deleted; snapshots
   keep the newest 100 per room. OK for a prototype on a PVC? If the PVC is
   small, say so and we add a purge job.

5. **README AI-usage badge.** The README placeholder has no badge yet; the
   house README rules require an explicit classification before writing the
   real README. The whole codebase is being generated by AI agents from your
   requirements — confirm the level you want stated.

6. **TypeScript 7.** Pinned 5.9.3 for predictability; happy to move to 7.x
   once the prototype runs.
